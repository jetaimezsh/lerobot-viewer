# LeRobot Viewer v4.0 - 模型回测框架设计文档

> 本文档按当前代码实际实现更新。它描述的是已经落地的 v4.0 模型回测框架，不再沿用早期 `/api/models/*` 和进程内 `MODEL_REGISTRY` 方案。

## 1. 当前实现范围

v4.0 的核心变化是把“模型”从临时注册记录改成可持久化的 **Model Profile**，并把回测任务改成后台单 worker 队列执行。

已实现：

| 能力 | 当前状态 |
|---|---|
| Model Profile 持久化 | 已实现，JSON 文件保存到 `state/model_profiles/` |
| 内置 profile 模板 | 已实现，ACT / Diffusion / VQ-BeT / Blank |
| Profile CRUD API | 已实现，统一使用 `/api/profiles/*` |
| LeRobot 官方 checkpoint 适配器 | 已实现，加载推理仅支持 Linux |
| 真实 episode 帧快速测试 | 已实现，`POST /api/profiles/{id}/test` |
| 多 profile x 多 episode 离线回测 | 已实现，请求参数为 `profile_ids` 和 `episodes` |
| 后台回测队列 | 已实现，`ThreadPoolExecutor(max_workers=1)` 顺序执行 |
| 回测历史持久化 | 已实现，保存到 `state/backtests/` |
| 回测结果导出 | 已实现，支持 JSON / CSV / HTML |
| 操作日志 | 已实现，通过 `app.operation_log.log_operation()` 记录关键操作 |

未实现或暂不支持：

| 能力 | 当前状态 |
|---|---|
| `/api/models/*` | 已废弃，当前代码不再提供 |
| 用户自定义模板保存 | 未实现，目前只有内置模板 GET |
| `custom_script` 适配器 | 未实现，只保留为后续扩展方向 |
| Windows 上 LeRobot 官方模型推理 | 不支持，环境检查会明确提示 Linux 要求 |
| 并行多 worker 推理 | 未实现，目前单 worker 顺序执行，避免显存和模型状态竞争 |

## 2. Model Profile

### 2.1 概念

Model Profile 是一个模型 checkpoint 的可复用配置档案。它包含：

- 模型显示信息：`id`、`name`、`description`
- checkpoint 信息：`checkpoint_path`、`adapter`、`device`
- 检查结果：`inspection`、`checkpoint_config`、`status`
- 推理参数：`runtime_params`
- 自定义参数：`extra_params`

Profile 数据保存在磁盘上，服务重启后仍然存在。当前存储位置：

```text
state/model_profiles/
├── act_pusht.json
├── diffusion_pusht.json
└── vq_bet_demo.json
```

`profile_id` 同时作为文件名，只允许匹配：

```text
^[a-z0-9_-]+$
```

### 2.2 Profile JSON 结构

当前 `app/profile_store.py` 实际读写的数据结构如下：

```json
{
  "id": "act_pusht",
  "name": "ACT pusht",
  "description": "LeRobot official ACT checkpoint.",
  "checkpoint_path": "/data/checkpoints/act_pusht",
  "adapter": "lerobot_official",
  "device": "cuda",
  "checkpoint_config": {},
  "runtime_params": {
    "policy_type": "act",
    "temporal_agg": true
  },
  "extra_params": {
    "notes": "local experiment"
  },
  "created_at": "2026-06-02 10:00:00",
  "updated_at": "2026-06-02 10:30:00",
  "inspection": {},
  "status": "created"
}
```

字段说明：

| 字段 | 来源 | 说明 |
|---|---|---|
| `id` | 用户输入 | 唯一标识，也是文件名 |
| `name` | 用户输入 | 页面展示名称 |
| `description` | 用户输入或模板 | 说明文本 |
| `checkpoint_path` | 用户输入 | checkpoint 目录或文件路径 |
| `adapter` | 用户选择或模板 | 当前主要是 `lerobot_official` |
| `device` | 用户输入 | `cuda`、`cuda:0`、`cpu` 等 |
| `checkpoint_config` | inspect 刷新 | checkpoint 配置的只读摘要 |
| `runtime_params` | 模板 + 用户编辑 | 适配器推理期参数 |
| `extra_params` | 用户编辑 | 自定义扩展参数，不由官方适配器直接解释 |
| `inspection` | inspect/load/test 写入 | checkpoint 检查结果和运行信息 |
| `status` | 系统维护 | `created`、`inspected`、`invalid`、`loaded` 等 |

### 2.3 运行时参数与自定义参数

当前前端已经从 JSON 文本框改成参数表格：

- `runtime_params`：运行期参数，由模板提供初始值，用户可以增删改。
- `extra_params`：用户自定义参数，也可以增删改。
- 每一行包含 key、类型、value 和删除按钮。
- 支持的值类型：`string`、`number`、`boolean`、`null`、`json`。

两类参数的边界：

| 参数类型 | 当前用途 |
|---|---|
| `runtime_params` | 传给适配器解释。`lerobot_official` 当前主要使用 `policy_type` 作为 factory 加载 fallback，`mock` 使用 `action` 和 `sleep_ms`。 |
| `extra_params` | 作为 profile 备注和扩展配置保存，当前官方适配器不会直接使用。 |
| `checkpoint_config` | inspect 从 checkpoint 配置文件读出的只读快照，不建议在 Web 上当作运行参数修改。 |

## 4. 适配器系统

### 4.1 文件结构

当前适配器目录：

```text
app/adapters/
├── __init__.py
├── lerobot_official.py
└── mock.py
```

`custom_script.py` 当前不存在，属于后续扩展项。

### 4.2 BacktestAdapter 基类

当前抽象基类定义在 `app/adapters/__init__.py`：

```python
class BacktestAdapter(ABC):
    adapter_name = "base"
    label = "Base"
    visible_in_ui = True
    test_only = False

    @classmethod
    def default_runtime_params(cls) -> dict[str, Any]: ...

    @classmethod
    def validate_params(cls, params: dict[str, Any]) -> list[str]: ...

    @classmethod
    def inspect_profile(cls, profile: dict[str, Any]) -> dict[str, Any]: ...

    @abstractmethod
    def load(self, profile: dict[str, Any]) -> None: ...

    @abstractmethod
    def predict(self, observation: dict[str, Any]) -> np.ndarray: ...

    @abstractmethod
    def reset_episode(self) -> None: ...

    @abstractmethod
    def unload(self) -> None: ...

    def runtime_info(self) -> dict[str, Any]: ...
```

注册表能力：

- `register_adapter(name, adapter_cls)`
- `get_adapter(name)`
- `list_adapters(include_test=False)`
- `load_builtin_adapters()`

### 4.3 当前适配器

| 适配器 | UI 可见 | 测试专用 | 说明 |
|---|---:|---:|---|
| `lerobot_official` | 是 | 否 | LeRobot 官方 checkpoint 适配器 |
| `mock` | 否 | 是 | 测试适配器，供 smoke test 使用 |

`lerobot_official` 行为：

- `inspect_profile()` 检查 checkpoint 路径、`config.json` 和模型权重文件。
- 如果发现 `config.json`，会读取关键配置到 `checkpoint_config`。
- `load()` 仅允许 Linux，Windows 会直接报错。
- 加载顺序优先尝试 `lerobot.policies.PreTrainedPolicy.from_pretrained()`。
- 如失败，再尝试 `lerobot.policies.factory.get_policy_class(policy_type).from_pretrained()`。
- `policy_type` 来自 `runtime_params.policy_type`。

`mock` 行为：

- 不在 UI 适配器列表展示。
- `runtime_params.action` 决定返回动作，默认 `[0.0, 0.0]`。
- `runtime_params.sleep_ms` 可模拟慢任务，用于队列测试。

`POST /api/backtests/jobs` 请求体：

```json
{
  "profile_ids": ["act_pusht", "diffusion_pusht"],
  "episodes": [
    {
      "dataset_path": "/data/pusht_v3",

```

## 6. 回测执行流程

### 6.1 多对多回测

回测支持多个 profile 与多个 episode 的组合：

```text
profiles: [p1, p2]
episodes: [dataset_a/ep0, dataset_b/ep5]

实际执行：
p1 x dataset_a/ep0
p1 x dataset_b/ep5
p2 x dataset_a/ep0
p2 x dataset_b/ep5
```

episode 可以来自不同数据集。前端从“LeRobot 数据 / Episode 播放”页面把选中的 episode 写入结构化样本列表，回测页面以表格展示：

- 数据集名称
- 数据集路径
- episode 编号
- 帧数
- 时长
- FPS
- task
- video keys

### 6.2 自动加载 profile

`run_backtest()` 执行时会对每个 `profile_id` 调用 `load_profile_adapter()`。

- 如果 profile 已加载，直接复用内存中的 adapter。
- 如果 profile 未加载，先 inspect，再 load。
- 如果某个 profile 加载失败，该 profile 对应的结果会记录为失败，其他 profile 继续执行。

### 6.3 单 worker 队列

后台任务由 `BACKTEST_EXECUTOR = ThreadPoolExecutor(max_workers=1)` 执行。

队列状态保存在进程内 `BACKTEST_JOBS`：

| 字段 | 说明 |
|---|---|
| `job_id` | 后台任务 ID |
| `status` | `queued`、`running`、`done`、`failed` |
| `profile_ids` | 本次任务选择的 profile |
| `episodes` | 本次任务选择的 episode |
| `created_at` / `started_at` / `finished_at` | 时间信息 |
| `run_id` | 完成后关联的历史结果 ID |
| `error` | 失败原因 |

当前队列是进程内队列，服务重启后任务队列本身不会恢复；已经完成并保存的回测历史会保留在 `state/backtests/`。

## 7. 回测结果与导出

结果保存逻辑位于 `app/backtest_store.py`。

每次 run 会保存：

- `run_id`
- `created_at`
- `profile_ids`
- `profiles`
- `episodes`
- `results`
- `summary`

为兼容旧前端或旧结果读取逻辑，当前保存结果中仍保留部分 `model_id` / `model_ids` 兼容别名，但新的主字段是 `profile_id` / `profile_ids`。

每条 result 包含：

- `profile_id`
- `profile_name`
- `profile_snapshot`
- `dataset_path`
- `episode_index`
- `status`
- `frames`
- `metrics`
- `series`
- `error`

导出格式：

| 格式 | 说明 |
|---|---|
| JSON | 完整 run 数据 |
| CSV | 扁平化 summary/result 表格 |
| HTML | 可读报告页面 |

## 8. Web UI 当前结构

当前 Web 不再把模型回测混在数据详情页里，而是分成两个根工作台：

| 根页面 | 职责 |
|---|---|
| LeRobot 数据 | 数据集查看、episode 播放、episode 级编辑、数据集级编辑 |
| 模型回测 | 模型档案、回测样本、任务队列、历史结果、图表对比 |

模型回测页面主要区域：

| 区域 | 当前实现 |
|---|---|
| Profile Editor | 内联编辑器，不是弹窗。可创建、保存、检查、加载、卸载、快速测试、删除 |
| Profiles | 已保存 profile 列表，显示状态、adapter、device、runtime params 摘要 |
| Backtest Selection | 表格展示从数据查看页加入的 episode |
| Model Choices | 勾选需要回测的 profile |
| Backtest Result | 回测矩阵、失败信息、结果摘要 |
| Backtest Queue | 后台任务队列表格，支持刷新和查看完成结果 |
| Backtest History | 历史 run 表格，支持查看 |
| Action Comparison | 选择 episode、action 维度和 profile 曲线后绘图 |

Profile 参数编辑当前使用表格：

- 运行期参数表：`#profileRuntimeParams`
- 自定义参数表：`#profileExtraParams`
- 添加运行期参数按钮：`#addRuntimeParam`
- 添加自定义参数按钮：`#addExtraParam`

## 9. 环境检查

`GET /api/profiles/env` 返回模型回测环境信息。当前检查项包括：

- 操作系统是否 Linux
- `torch`
- `lerobot`
- `safetensors`
- `numpy`
- `pandas`
- CUDA 是否可用、设备数量、设备名称
- 已加载 profile
- 可用 adapter
- worker 状态

`ready_for_lerobot_backtest` 的条件是：

```text
is_linux == true
并且 torch、lerobot 等 LeRobot 官方推理必需依赖可导入
```

因此在 Windows 上，即使安装了 Python 包，也会被标记为不满足官方 LeRobot 模型推理条件。

## 10. 操作日志

当前系统在关键 API 和后台任务中调用 `log_operation()` 记录操作结果，包括但不限于：

- profile 环境检查
- profile 创建、更新、删除
- profile inspect/load/unload/test
- backtest run
- backtest job create/done/failed
- backtest export

日志用于排查用户在 Web 上执行了哪些动作，以及动作是否成功。

## 12. 后续扩展方向

### 12.1 自定义脚本适配器

后续可以新增 `app/adapters/custom_script.py`，通过子进程 JSONL 协议接入任意模型：

```text
server -> script: {"type": "predict", "observation": {...}}
script -> server: {"type": "action", "action": [0.1, 0.2]}
```

建议约束：

- 每条消息一行 JSON。
- stdout 只输出协议消息，日志走 stderr。
- load / predict / reset / close 都有明确超时。
- 子进程环境与主服务隔离。

### 12.2 用户自定义模板

后续可以补齐用户模板系统：

- `POST /api/profiles/templates`
- `DELETE /api/profiles/templates/{template_id}`
- 存储目录 `state/model_profile_templates/` 或 `state/model_profiles/.templates/`
- 创建 profile 时可选择内置模板或用户模板

### 12.3 持久化任务队列

当前后台任务队列是进程内结构。后续如果要支持服务重启恢复，可以把 queued/running/done/failed 状态持久化到 `state/backtest_jobs/`，启动时恢复未完成任务。

### 12.4 Linux 推理 worker 化

当前 worker 是线程级后台执行。后续如果要支持更稳定的 Linux GPU 推理，应考虑独立 worker 进程：

- Web 服务只负责任务提交和结果查询。
- Linux worker 负责模型加载和推理。
- 队列状态、任务输入、任务输出都落盘或进入轻量数据库。
- worker 崩溃不影响 Web 服务。

## 13. 迁移说明

v4.0 已经直接放弃旧的 `/api/models/*` 设计：

| 旧设计 | v4.0 替代 |
|---|---|
| `MODEL_REGISTRY` 进程内字典 | `state/model_profiles/*.json` |
| `/api/models/register` | `POST /api/profiles` |
| `/api/models/inspect` | `POST /api/profiles/{id}/inspect` |
| `/api/models/load` | `POST /api/profiles/{id}/load` |
| `/api/models/unload` | `POST /api/profiles/{id}/unload` |
| `/api/models/delete` | `DELETE /api/profiles/{id}` |
| 请求字段 `model_ids` | 请求字段 `profile_ids` |

旧的进程内模型注册记录无法迁移，因为服务重启后本来就会丢失。用户需要在 v4.0 中重新创建 profile。

历史回测结果仍可读取。为了兼容旧结果展示，保存层保留了 `model_id` / `model_ids` 别名，但新的代码和文档都应优先使用 `profile_id` / `profile_ids`。
